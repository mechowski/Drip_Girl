# Drip Girl

Локальный веб-прототип управления производством дрип-кофе: от регистрации обжаренного лота до сборки наборов, FIFO-списания и ежедневного архива.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Vite покажет локальный адрес. Для production-сборки:

```bash
npm run build
npm run preview
```

Административный пароль по умолчанию: **1337**. Его можно изменить в админпанели. Сессия администратора хранится только в текущей вкладке.

## Реализовано

- Лоты с UUID, дроблением по форматам и назначениям, контролем общего веса и расчётом выхода.
- Объединение задач изготовления по формату, частичные приходы, ответственные, списание кофе и история.
- Дегазация 1–5 календарных дней, локальный календарь нерабочих дней, подтверждение переносов и сценарий «Запаковать в Б/у».
- Сток с физическим остатком и резервом, фильтрами, переназначением, ручными корректировками и журналом транзакций.
- Импорт всех колонок ×16/×30 из публичной Google Sheets или CSV, выбор листов, снимок последней успешной версии, псевдонимы несопоставленных лотов.
- Ручные ×6, Мега ×6, Подписка и Лимита; отключение составов без изменения уже запущенных заданий.
- Дневной план из нескольких составов, повторная проверка стока, атомарное резервирование и задания всему участку.
- Несколько отчётов сборщиков по одному заданию, предупреждения администратору, FIFO-списание по нескольким производственным партиям.
- Административное исправление отчётов с обратным восстановлением стока/резерва и обязательным комментарием.
- Завершение дня, перенос остатков вместе с резервами, компактный дневной отчёт и постоянный архив.
- Справочник сотрудников, внутренние предупреждения, аудит действий.
- IndexedDB через Dexie, версия схемы и миграция, полный экспорт/импорт JSON с предварительным просмотром.
- Демонстрационные данные и их отдельное удаление.
- Светлая/тёмная тема, адаптивная мобильная навигация, состояния загрузки и пустых данных, reduced motion.

## Тесты

```bash
npm test
npx playwright install chromium
npm run build
npm run test:e2e
```

Проверяются коэффициенты, округление, дробление, объединение задач, остатки, календарь, составы, резервы, FIFO, откат при нехватке, два отчёта, административное исправление и резервные копии. E2E проходит путь от входа администратора и демонстрационного производства до двух отчётов, закрытия дня, архива, перезагрузки, экспорта и повторного импорта.

## Структура

- `src/domain` — типы и чистые бизнес-расчёты.
- `src/persistence` — IndexedDB, транзакции, миграции, репозиторий и резервные копии.
- `src/integrations` — Google Sheets и контракты будущих внешних адаптеров.
- `src/pages` — экраны приложения без встроенной бизнес-логики расчётов.
- `src/ui` — общие интерфейсные компоненты и административный контекст.
- `src/tests` — Vitest и fake-indexeddb.
- `e2e` — Playwright.

## Google Sheets

Таблица должна быть публичной или опубликованной для чтения. Название листа должно содержать `×16` или `×30`. Первая строка содержит названия наборов, а строки лотов — значения вида `Страна / название`. Для ×16 используются четыре лота по 4 дрипа, для ×30 — три лота по 10. Остальные строки сохраняются как метаданные.

Ошибка сети или структуры не затирает последний успешный снимок. Автоматическая проверка выполняется раз в 24 часа только пока приложение открыто. Доступность импорта зависит от публикации таблицы и CORS-политики Google.

## Ограничения локальной версии

- Данные доступны только в текущем браузере на текущем устройстве.
- Разные устройства не синхронизируются.
- Очистка данных браузера может удалить информацию — регулярно экспортируйте JSON.
- Автоматическое обновление Google Sheets работает, только пока приложение открыто.
- Пароль администратора не является полноценной серверной защитой.
- Производственный календарь РФ хранится локально и требует ручного обновления праздников и переносов.
- Для совместной работы нескольких сотрудников потребуется backend.
- Backend, Docker, серверная БД, Битрикс, приложение обжарки, сборка со СМОЛ и автоматический структурированный учёт брака намеренно не входят в эту версию.

## Переход на сервер

Доменные расчёты не зависят от Dexie и могут быть перенесены без переписывания. Репозиторий IndexedDB заменяется API-адаптером; для совместной работы понадобятся серверная авторизация, роли, транзакции БД, блокировки резервов, аудит и серверная синхронизация Google Sheets. Контракты внешних уведомлений, обжарки и удалённого хранения выделены в `src/integrations/future.ts`.
