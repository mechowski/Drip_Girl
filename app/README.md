# Дриповщица

Локальный прототип управления производством дрип-кофе. В одном интерфейсе можно вести обжаренные лоты, планировать изготовление, принимать продукцию на сток, собирать наборы и архивировать отчёты по сменам.

## Запуск

Понадобятся Node.js 22.12 или новее и npm.

```bash
cd app
npm ci
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Для запуска через **Go Live** откройте в VS Code корневую папку проекта (уровнем выше `app`). После `npm ci` выполните `npm run build` в папке `app`, установите расширение **Live Server** (`ritwickdey.LiveServer`), если его ещё нет, и нажмите **Go Live**. Расширение откроет тот же адрес. После изменения исходников повторите `npm run build`. Используйте один способ запуска за раз, чтобы порт 3000 был свободен.

Кнопка **Администратор** открывает вход. Начальный пароль — `1337`. Его можно изменить в настройках производства.

Для проверки на телефоне в той же сети запустите `npm run dev -- --host 0.0.0.0` и откройте на телефоне сетевой адрес, который покажет Vite. У телефона будет своё локальное хранилище.

Готовая статическая сборка создаётся командой `npm run build` в каталоге `app/dist`. Для локальной проверки сборки запустите `npm run preview`. При размещении статических файлов настройте возврат `index.html` для клиентских маршрутов. Бизнес-операции выполняются в браузере.

## Производственный сценарий

1. Войдите как администратор и добавьте сотрудников. В админпанели можно заполнить базу демонстрационными лотами, сотрудниками, стоком и составом ×16.
2. Создайте лот, распределите вес по форматам и назначениям. Календарь рассчитает дегазацию, предложит перенос или покажет срок упаковки в Б/у.
3. Запишите фактически изготовленное количество. Каждая операция даёт отдельный приход на сток. На карточке задачи видны история, остаток задачи и расчётный остаток кофе.
4. Создайте ручной состав либо импортируйте ×16 и ×30. Для неизвестных названий выберите исходный лот. Соответствие сохранится как псевдоним.
5. Добавьте составы в план и подтвердите резерв. Система повторно проверит доступное количество, а при использовании другого назначения запросит подтверждение.
6. На вкладке заданий сборщик выбирает свою фамилию и отправляет результат. Каждая отправка списывает сток из резерва по FIFO и сохраняет детализацию.
7. В отчётах завершите день. Архив сохранит итог смены, а открытые задания перейдут на следующий рабочий день с остатком резерва.

## Google Sheets

В админпанели откройте **Настроить импорт**. Вставьте ссылку на общедоступную таблицу Google Sheets или на таблицу, опубликованную для чтения, нажмите **Получить листы**, выберите нужные и нажмите **Обновить составы**. Требуется сеть. Приватные таблицы с авторизацией в этой версии не поддерживаются.

На листе формата ×16 или ×30 каждая колонка справа от подписей содержит отдельный состав. Для примера в ×16 используются четыре позиции по 4 пакета.

```csv
Набор,Кофейная коллекция ×16
Страна 1 / локация 1,Эфиопия / Гуджи
Страна 2 / локация 2,Колумбия / Уила
Страна 3 / локация 3,Бразилия / Серрадо
Страна 4 / локация 4,Кения / Ньери
```

В ×30 используются три позиции по 10 пакетов. Парсер также принимает пары строк «Страна 1» и «Название лота 1». Вкусовые и другие атрибуты сохраняются как метаданные. Импорт из CSV доступен для локальной проверки. При ошибке чтения выбранных листов сохраняется последняя успешная загрузка.

## Календарь и резервные копии

Встроенный календарь содержит праздничные переносы РФ на 2026 год. Для другого периода загрузите JSON с массивами `nonWorkingDays` и `workingDays` в формате дат `ГГГГ-ММ-ДД`. Указанные администратором исключения имеют приоритет. Даты вне загруженного периода учитывают субботу и воскресенье.

В разделе **Админпанель → Резервные копии** можно скачать полный JSON, проверить количество записей при импорте и явно подтвердить замену базы. Схема IndexedDB обновляется автоматически. Архив хранится без ограничения по сроку в пределах доступной квоты браузера.

## Проверки

```bash
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Модульные тесты проверяют расчёты и календарь, сток и резервы, обработку импорта, версионирование и сохранение истории. Playwright проверяет в Chromium производственный путь от входа и регистрации лота до отчётов, архива, перезагрузки и восстановления JSON. Ответы Google Sheets в сценариях контролируются тестами.

## Ограничения прототипа

- IndexedDB привязано к браузеру, профилю, устройству и адресу приложения. Используйте один адрес при повторном запуске.
- Синхронизации между устройствами нет. Очистка данных браузера может удалить базу. Резервную копию можно хранить отдельно.
- Автоматическое обновление Google Sheets проверяет срок в открытом приложении. В закрытой вкладке оно не выполняется.
- Локальный пароль ограничивает действия через интерфейс. Серверной аутентификации и защиты от пользователя с доступом к браузеру нет.
- Для одновременной работы сотрудников с разных устройств потребуется backend.

## Структура и переход на сервер

Чистые расчёты находятся в `src/domain`. Транзакции, миграции, резервные копии и чтение снимка работают через `src/persistence`. Представление собрано в `src/pages` и `src/ui`. Чтение Google Sheets и контракты будущих интеграций находятся в `src/integrations`.

Для многопользовательской версии понадобятся API и общая база, серверные права доступа, атомарное резервирование и списание, идемпотентные операции и перенос существующих локальных данных. Периодическое обновление Google Sheets следует перенести в серверное задание. Расчёты выхода, календаря, лимитирующих ингредиентов и FIFO можно сохранить как доменные функции.
